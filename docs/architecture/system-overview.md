# System Overview

## Architecture stance

Echorym starts as a documented system of concepts, schemas, and prototype loops. Runtime architecture should emerge from validated prototype needs.

## Initial layers

- **World layer**: world state, regions, gates, anchors, dormant trust networks.
- **Entity layer**: entities, relationships, trust posture, memory links.
- **Player layer**: intent, known signals, choices, state changes.
- **Event layer**: decisions, observations, consequences, uncertainty.
- **Memory layer**: traces that affect future interpretation and world response.
- **Evaluation layer**: coherence, trust, signal integrity, resilience, and reproducibility checks.

## Experiment loop

The existing repo framing of data -> model -> evaluation -> reflection remains important. In Echorym, that loop evaluates adaptive coherence-world behavior rather than reward-maximizing policy alone.
