# Development Charter

## Purpose

This repository exists to make Echorym legible, testable, and reusable without prematurely locking the project to a game engine, AI model, programming language, or research method.

The near-term goal is to create a shared scaffold for worldbuilding, adaptive systems design, simulation, experiment design, and eventual prototypes.

## Development stance

- Documentation comes first when a concept is still fluid.
- Schemas should describe the minimum stable data needed for experiments.
- Prototypes should test one loop at a time.
- Research references should be treated as inputs for review, not automatic authority.
- External content should not be promoted into official context without human approval.

## Scope boundaries

Echorym may later support games, simulations, agent experiments, visual worldbuilding, and research applications. This repository should remain flexible enough for all of those paths.

Do not treat early terms, thresholds, schemas, or mechanics as final doctrine. They are starting contracts for iteration.

## Provenance practice

When adding material, record where it came from:

- User-authored direction
- Existing repository content
- Approved project notes
- Experiment output
- External research source
- AI-drafted proposal awaiting review

External sources belong in reviewed research notes or untrusted intake until approved.

## Review expectations

Major changes should explain:

- What changed
- Why it changed
- Which prototype, schema, or research thread it affects
- Whether it changes public project framing
- Whether any approval gate was needed
